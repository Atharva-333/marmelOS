# Contributing to marmelOS

Thank you for your interest in marmelOS.

This document describes the intended contribution process. The final contribution terms will be published before public contributions are accepted.

## 1. Ways to contribute

Potential contributions include:

- Bug reports.
- Reproducible test cases.
- Feature suggestions.
- Documentation improvements.
- Code improvements and patches.
- Hardware compatibility reports.
- Usability feedback.

## 2. Before submitting code

Please first check whether the issue or proposed change is already being discussed. For substantial changes, describe the problem and proposed approach before investing in a large patch.

## 3. Review and acceptance

All submissions are subject to review. The maintainer decides whether a contribution is accepted and may request changes or decline it.

Submitting a contribution does not automatically mean it will be merged or included in a release.

## 4. Ownership and permission

The project does not intend to automatically acquire ownership of every submitted contribution. The ownership, license, publication rights, and attribution arrangements for a contribution should be agreed in writing.

Do not submit code that you do not have the right to contribute.

## 5. Public patches and redistribution

The project's source-visibility and redistribution rules are described in [Licensing and Permissions](LICENSING_AND_PERMISSIONS.md). Publicly distributing patches or modified builds may require written permission under the final license.

## 6. Code of conduct

A separate Code of Conduct will be published if and when the project opens a public community contribution process.
