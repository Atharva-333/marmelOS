# Project Philosophy

## 1. Central idea

marmelOS should adapt its behaviour to what the user is doing without taking control away from the user.

The operating system should feel like one coherent environment that can change its priorities according to the activity—not three unrelated products joined together.

## 2. User agency

The user should remain in control of their machine.

Adaptation should be understandable, reversible, and appropriately configurable. A mode should not silently make destructive or surprising changes. Where a system action has meaningful consequences, the user should have a clear way to understand and control it.

## 3. Purposeful experiences

Each mode should exist for a reason:

- Ember is about prioritising a game.
- Dusk is about sustained, efficient development work.
- Dawn is about expressive everyday computing and privacy-conscious interaction.

A mode should not be considered successful merely because it changes appearance. Its behaviour should support its stated purpose.

## 4. Continuity

Changing modes will not unnecessarily interrupt the user's work. The shared memory system is intended to preserve useful context across activities, subject to explicit privacy and user-control boundaries.

## 5. Privacy and trust

Privacy should be part of system design, not a marketing label. Data collection, local processing, retention, deletion, permissions, and external communication must be documented and testable.

## 6. Engineering honesty

marmelOS should distinguish between:

- A concept and an implemented feature.
- An intended benefit and a measured result.
- A prototype and a supported release.
- A security mechanism and a security guarantee.

Performance and security claims will be backed by repeatable testing.
