# Source Visibility, Licensing and Permissions

**Status:** Policy summary for planning. This is *not* the final legal license.

## 1. Licensing direction

marmelOS is intended to use a **visible-source proprietary licensing model**. Users should be able to inspect the source, but source visibility does not automatically grant permission to redistribute, publish forks, or commercially reuse proprietary implementation code.

marmelOS should not be described as OSI-approved open-source software unless its actual license meets that definition.

## 2. Intended user permissions

The current policy direction is:

| Activity | Intended permission |
|---|---|
| View and inspect source code | Allowed |
| Download and install official releases | Allowed |
| Use marmelOS personally | Allowed |
| Use marmelOS for commercial work | Allowed |
| Share an original, unmodified official release | Allowed |
| Share official download links | Allowed |
| Privately modify a personal copy | Allowed |
| Keep private modifications and backups | Allowed |
| Submit fixes for consideration | Allowed |
| Publish a modified distribution or unofficial build | Not allowed without written permission |
| Publish a public fork | Not allowed without written permission |
| Redistribute modified proprietary source | Not allowed without written permission |
| Reuse proprietary implementation code in another product | Not allowed without written permission |
| Repackage or preinstall for resale | Requires written permission |

The final license must define the precise scope of each permission and any conditions, including preservation of notices and approved mirrors.

## 3. Contributions

Submitting a patch does not automatically transfer ownership of the contribution to the project maintainer. Ownership, licensing, attribution, and permission to include or publish each contribution should be agreed in writing.

The project may accept or decline contributions at its discretion, subject to applicable law and any agreement with the contributor.

## 4. Third-party components

marmelOS will depend on third-party software, including Linux and potentially other open-source components. Those components retain their own licenses and notices.

## 5. Required before public release

Before the first public release, will publish a complete license that clearly addresses:

- Source inspection and access.
- Downloading, installation, and use.
- Original release redistribution.
- Private modification.
- Public forks and modified redistribution.
- Commercial use and resale.
- Contributions and ownership.
- Trademarks and branding.
- Warranty disclaimer and limitation of liability, subject to applicable law.
- Third-party components and notices.
- Termination, enforcement, and applicable jurisdiction.
- Obtaining qualified legal review before relying on the license for public distribution.
